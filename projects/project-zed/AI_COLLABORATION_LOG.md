# AI Collaboration Log

## How I Used AI

I used ChatGPT during Project Zed for troubleshooting, brainstorming, and helping me take some of my ideas a little further. I knew that I wanted to build something that would be useful to me in the workplace. I used AI for help when I got stuck or when I wanted to see if an idea I had was possible with the JavaScript I already knew.

## Planning the Project

At the beginning, I used ChatGPT to help me narrow down my idea and make sure it was something I could realistically complete for the project. It was very helpful for brainstorming and knowing my limitations. My original idea was a pretty basic task tracker. As I worked on it, I started thinking of ways to make it more useful, like creating a project once and then choosing it from a dropdown instead of entering the same project information every time.

I learned this idea while creating our favorites tracker, and I really liked the feature. It saves time and also helps eliminate misspellings.

## Debugging a JavaScript Error

One of the most helpful times I used AI was when my tasks suddenly stopped displaying. I shared my JavaScript and ChatGPT found that I was missing a closing curly brace. It was a very small error, but it stopped the rest of the code from working and I could not find the problem.

That was helpful because it reminded me how one missing character can affect a much larger section of JavaScript. It also helped me learn to look at where functions begin and end when I am troubleshooting.

## Troubleshooting GitHub Pages

I also used AI when my live GitHub Pages site was not loading the way I expected. The repository was working, but I had to make sure GitHub Pages was publishing the correct version of the project and that my files in the repository matched the version I was testing locally.

Working through that with AI was helpful because it was not really a coding problem. It helped me better understand the connection between my local files, GitHub repository, and the live GitHub Pages site.

## Going Beyond the Basic Requirements

Once the main part of the app was working, I used AI to help me think through some enhancements that went beyond the basic assignment.

Some of those enhancements included:

- organizing tasks by project
- creating an active project dropdown
- adding task details
- automatically moving past due tasks to the top
- moving completed tasks to the bottom
- completing and reopening projects
- adding optional notes to completed projects
- creating dashboard filters for active, past due, due today, and completed work
- editing projects and tasks
- archiving and restoring projects
- exporting project and task information to a CSV file
- adding a delete project option inside the Edit Project area

I did not add every idea that came up. I tried to choose features that made sense for how I would actually use the tracker.

## Learning Something New

The biggest new technique for me was working with JavaScript dates. I used AI to help me understand how JavaScript could compare a task due date with today's date and decide whether the task was Past Due, Due Today, or In Process.

I also color coded the cards based on those statuses and used the same information to help organize the tasks by priority. I wanted to understand what the Date code was actually doing instead of just adding it, so I used AI to walk through how the task date was compared to today's date and why setting the time to midnight made the comparison work.

This was probably the part of the project where AI helped me move to the next level beyond what I had done in my earlier projects.

## Design Feedback and Revision

I also used AI while thinking through the visual design of the project. During my final walkthrough, I received feedback that the desktop version gave too much visual attention to the office image on the side and that the mobile version had a clearer hierarchy.

I used that feedback to rethink the layout. I ultimately incorporated the office graphic into the green header area so that it supported the design without competing with the actual Task Tracker. AI could help me explore different technical ways to do that, but I still had to decide which layout looked best and supported the purpose of the app.

## Sample AI Conversations

Here are a few examples of the types of conversations I had with ChatGPT during the project:

**Example 1: Debugging**

I asked why my tasks had stopped displaying after I made a change to my JavaScript. ChatGPT reviewed the code and pointed out that I was missing a closing curly brace. I corrected the error and tested the app again.

**Example 2: Learning JavaScript Dates**

I asked how JavaScript could tell whether a task was past due, due today, or still in process. ChatGPT explained how Date objects could be compared and why the current date should be set to midnight before comparing it with a task due date.

**Example 3: Improving the Project Workflow**

I asked whether it would make more sense to create a project once and then select it from a dropdown when adding tasks. We talked through how that could reduce repeated typing and misspellings, and I decided to use that structure.

**Example 4: Design Revision**

After receiving feedback on my desktop layout, I asked how I could keep the office graphic without letting it compete with the application. I considered several layouts and decided to incorporate the image into the top header area instead.

## What I Learned About Using AI

AI was the most helpful to me when I already had an idea or a problem that I was trying to solve. I was able to use it to troubleshoot areas or give me ideas for how I could enhance my project without going too far above what I had already learned.

It was especially helpful for finding small coding mistakes that are really hard to see once you have been looking at the same code for a long time and everything starts to look the same.

I also learned that AI can give me several possible ways to solve a problem, but I still have to decide which solution makes the most sense for my project. Testing the code, deciding which features were useful, and making the final design choices were still my responsibility.
