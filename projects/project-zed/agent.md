# Task Tracker Project Status

## Where I Am

The main parts of my Task Tracker are complete and working. I started with a basic task tracker, but as I tested it I continued to make changes that made the app more useful and easier to organize. Testing the app helped me see what was working, what could be improved, and which additional features would actually be useful. I am now finishing final testing, documentation, and small design refinements.

## What Is Working

- Users can create a project and add a project due date
- Active projects appear in a dropdown when adding a task
- Users can add tasks, due dates, and optional details
- Tasks are grouped under the project they belong to
- Projects are organized by month
- Tasks show as Past Due, Due Today, In Process, or Completed
- Past due tasks move to the top
- In process tasks stay in the middle
- Completed tasks move to the bottom
- Users can open and close task details
- Users can mark a task complete or incomplete
- Users can delete tasks
- Users can edit projects and tasks
- Users can mark an entire project complete
- Completed projects collapse so completed tasks are hidden
- Completed projects are removed from the active project dropdown
- Completed projects can be reopened
- Users can add optional notes to a completed project
- Projects can be archived and restored
- Projects can be deleted from the Edit Project area
- The dashboard shows Active Projects, Past Due, Due Today, and Completed totals
- Dashboard buttons can be used to filter the displayed projects and tasks
- Project and task information can be exported to a CSV file
- Projects and tasks are saved with localStorage
- The app is working on GitHub Pages
- The layout adjusts for smaller screens
- The office graphic is incorporated into the header to support the design without taking attention away from the application

## What I Am Still Working On

I am finishing the final project documentation and reflection, checking the live GitHub Pages version, and making sure the Project Zed version in my portfolio matches the final standalone version.

## What Changed From My Original Plan

My original idea was much more basic. I planned to add a project name, task, and deadline and then display the tasks by status. However, as I worked on the project, I realized I did not want to enter the same project name and project due date every time I added a task.

I changed the app so a project is created once and then selected from a dropdown when adding tasks. This was an idea that I took from our favorites tracker, which made organization easier and helped eliminate misspellings.

I also added task details, project completion, project notes, editing, archiving, dashboard filters, CSV export, and automatic task organization because those features made the tracker more useful. Color coding was something that I did not consider until I started using the app and realized it was helpful to have a quick visual of where each task stood.

The design also changed after my project walkthrough. I originally placed the office graphic beside the application on desktop. After receiving feedback about the visual hierarchy, I moved the graphic into the green header so it became part of the interface instead of competing with the Task Tracker.

## If I Had More Time

If I had more time, I would like to make the data available across different devices instead of storing it only in localStorage. Right now the projects and tasks are saved in the browser being used, so the same information does not automatically appear when the app is opened on another computer.

I would also like to explore exporting completed projects into a more detailed spreadsheet format and possibly creating yearly archives. That could make the tracker even more useful for keeping a long-term record of completed work.
